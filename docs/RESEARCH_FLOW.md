# Research Narrative and Experimental Flow

## Research question

The project asks whether GPT-2 Small's apparent preference for correct answers to simple addition prompts is supported by a general, addition-specific internal mechanism. It also asks whether observed logit patterns can instead be explained by token baselines, prompt structure, repeated operands, or other learned associations.

The initial working account emphasized a heuristic-dominant, operator-sensitive pathway for apparent addition behavior. Behavioral baselines and competing explanations narrowed that account: the tested suite does not identify a general, reliably functioning addition mechanism. A target-dependent equal-operand preference is measured under selected conditions, but its mechanism is unresolved. Notebook code and saved outputs support the operator summaries; per-prompt operator scores are unavailable.

## Flow at a glance

Behavioral baseline → matched controls → token and unembedding baselines → corrected DLA → causal interventions → doubles effect → operator/connector substitutions → corpus proxy audit → next causal validation.

The first eight stages are completed or closed at the status indicated below. The final validation stage is a proposed next experiment; it was not completed in this project.

## Reading the narrative

The experiment did not move from a clean hypothesis to a single confirming test. An initial addition-circuit interpretation motivated component analysis. Numerical checks questioned DLA scale and highlighted a static unembedding term. Better baselines and distribution-preserving interventions weakened specific head claims. The addition grid supports a parity pattern that changes with target range. A target-dependent equal-operand preference is measured in the saved prompt scores. The final notebook records a raw corpus-query collection but no correlation; earlier summary correlations are historical, and individual API responses and formatted prompt-level scores remain unavailable.

This sequence explains why the final claim is narrower than the starting hypothesis. The detailed correction history, including the final exploratory component screen, is in the single [audit trail](audit_trail.md). This document presents the research reasoning path rather than retelling every debugging step.
